# AI 品牌可见性诊断

## 诊断维度

诊断围绕四类问题组织，但只根据用户资料和 MCP 实际返回结果下结论：

1. **品牌实体存在度**：官网、企业介绍、产品、团队、行业定位和名称是否清楚一致。
2. **AI 知识覆盖**：模型能否回答品牌是谁、做什么、适合谁、优势证据和相关品牌。
3. **内容资产覆盖**：是否具备知识页、行业文章、案例、FAQ、新闻报道和可验证引用。
4. **AI 答案占位**：品牌是否在目标问题中被提及、如何被描述、引用什么来源、是否返回排名。

工具未返回评分时，不生成“品牌实体 40%”或“综合评分 28 分”等数字。改用“已验证、部分验证、缺少证据、存在冲突”描述，并列明依据。

## 创建与确认

1. 收集品牌词、诊断目标和需要使用的模型。当前只支持 `doubao`、`deepseek`、`qianwen`、`wenxin`，分别对应豆包、DeepSeek、千问和文心一言。
2. 调用 `geo_create_brand_diagnosis`，保存诊断任务编号和本次幂等键。创建问题阶段不消耗品牌诊断额度。
3. 使用 `geo_get_brand_diagnosis` 查询，直到 `raw_status` 为 `questions_ready`、状态失败或出现明确错误。
4. 完整展示问题编号和文本。允许用户修改问题文本，或使用空字符串删除指定问题。
5. 明确告知确认后会消耗一次品牌诊断额度，并等待用户确认。
6. 调用 `geo_confirm_brand_diagnosis`。省略问题列表表示保留全部系统生成问题；用户修改问题后不得省略问题列表。
7. 保存确认操作的幂等键，继续调用 `geo_get_brand_diagnosis`，直到完成或失败。

## 结果解读

1. 报告诊断日期、任务状态、品牌词、问题集合和使用模型。
2. 分别整理 `brand_performance`、`model_results`、`sources` 和 `rankings`。
3. 按问题说明品牌是否出现、回答是否准确、有哪些来源和占位品牌，不跨模型合并成工具未提供的总分。
4. 将 AI 答案占位品牌与现实市场竞品分开，现实竞品需另行验证。
5. 将平台事实、用户事实、分析推断和行动建议分开。
6. 将问题映射到实体修正、内容资产、第三方引用和复测计划。

ChatGPT 相关问题可以进入本诊断流程设计，但当前工具无法执行 ChatGPT 实测。不得用其他模型结果替代 ChatGPT 结果，也不得声称覆盖所有 AI 平台。

## 隔离与状态边界

- 只访问当前 MCP Key 所属账号和绑定站点的诊断任务。
- 查询不到用户给出的任务编号时，不搜索其他账号或系统级任务。
- 额度不足时保留当前待确认任务，提示用户处理套餐后使用同一任务继续确认。
- 任务未完成时只报告进度，不提前生成最终结论。
