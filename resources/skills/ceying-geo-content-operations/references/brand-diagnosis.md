# 品牌诊断

## 创建与确认

1. 收集品牌词和需要使用的模型。模型只使用工具 Schema 当前允许的值。
2. 调用 `geo_create_brand_diagnosis`，保存返回的诊断任务编号和本次幂等键。创建问题阶段不消耗品牌诊断额度。
3. 使用 `geo_get_brand_diagnosis` 查询，直到 `raw_status` 为 `questions_ready`、状态失败或出现明确错误。
4. 当问题可确认时，完整展示问题编号和文本。允许用户修改问题文本或用空字符串删除指定问题。
5. 明确告知确认后会消耗一次品牌诊断额度，并等待用户确认。
6. 调用 `geo_confirm_brand_diagnosis`。省略问题列表表示保留全部系统生成问题；不要在用户修改问题后省略问题列表。
7. 保存确认操作的幂等键，继续调用 `geo_get_brand_diagnosis`，直到完成或失败。

## 结果解读

- 先报告任务状态、品牌词和使用模型。
- 分别整理 `brand_performance`、`model_results`、`sources` 和 `rankings`。
- 引用具体来源和排名时保持 MCP 返回的模型、链接和数值，不补造缺失来源。
- 将事实结果与运营建议分开。运营建议可以基于诊断结果推导，但必须标明为建议。
- 任务未完成时只报告当前进度，不提前生成最终诊断结论。

## 隔离边界

- 只访问当前 MCP Key 所属账号和绑定站点的诊断任务。
- 查询不到用户给出的任务编号时，不尝试搜索其他账号或系统级任务。
- 额度不足时保留当前待确认任务，提示用户处理套餐后再使用同一任务继续确认。
