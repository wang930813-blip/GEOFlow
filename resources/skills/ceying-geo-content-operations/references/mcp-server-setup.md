# MCP Server 安装与 Key 配置

## 连接目标

建立名称为 `ceying-geo` 的 MCP 连接，并确认当前会话发现目标业务所需的 `geo_*` 工具。Skill 不内置服务地址或凭证，因为服务地址取决于实际部署，MCP Key 绑定具体账号、站点和权限。

## 未连接时的首轮动作

完全未发现 `geo_*` 工具时，本流程立即接管当前任务。不得只提示“尚未连接”后继续输出品牌方案或收集品牌资料。

按以下顺序执行首轮响应：

1. 报告检测结果：当前会话未发现 ceying-geo 的 `geo_*` 工具，尚不能读取平台数据或执行平台动作。
2. 立即检查当前客户端是否提供 MCP 连接管理、依赖安装、MCP 市场或受控配置编辑能力；存在时直接调用，不先让用户手动操作。
3. 无法自动识别客户端或安装入口时，只询问“当前使用的 AI 客户端名称和版本”，不要同时追问品牌、行业、客户或竞品信息。
4. 已识别客户端但缺少服务地址时，给出“登录策影GEO、切换目标站点、进入账号与权益下的 MCP Server、复制公网地址”的当前步骤，并只让用户返回服务地址。服务地址不是密钥，可以在对话中提供。
5. 地址已具备但缺少 Key 时，打开或指向客户端的安全凭证入口，引导用户在策影GEO的 MCP Server 页面创建最小权限 Key并直接填入该入口。只让用户回复“已完成”，不得让用户返回 Key。
6. 用户完成后继续保存、重载、发现工具和只读验证。验证失败时进入对应排障状态，不返回品牌业务流程。

每一轮只处理当前安装状态的一个阻塞点，但必须持续推进安装状态机。只有连接验证成功，或用户明确选择暂不安装并只做纯策略，才能退出本流程。

## 判断当前状态

| 当前状态 | 处理方式 |
| --- | --- |
| 完全没有 `geo_*` 工具 | 进入 MCP Server 安装与连接流程 |
| 有部分 `geo_*` 工具 | MCP 已连接，根据目标工具补充最小 Scope |
| 工具调用返回 `401` | 检查 Key 是否完整、过期、撤销或填入了错误位置 |
| 工具调用返回 `403` | 检查账号、站点状态及目标能力所需 Scope |
| MCP 地址连接失败或连接端点返回 `404` | 回到平台复制当前站点展示的完整 MCP Server 地址并核对反向代理 |
| 工具可发现且读取调用成功 | 连接有效，进入对应业务流程 |

## 自动安装引导

1. 识别当前 AI 应用是否提供 MCP 依赖安装、MCP 市场、连接管理或配置编辑能力。
2. 客户端能够处理 Skill 的 MCP 依赖声明时，主动选择 `ceying-geo` 依赖并执行以下动作：
   - 查询是否已存在同名连接，避免创建重复配置。
   - 已存在且可用时直接复用；已存在但参数不完整时只补充缺失项，不覆盖其他连接。
   - 不存在时创建 Streamable HTTP 连接，并预填连接名称和客户端已能确认的参数。
3. 缺少真实服务地址时，暂停在地址字段，引导用户从策影GEO平台取得当前站点地址；用户提供地址后继续完成配置，不要求用户重新执行前序步骤。
4. 客户端提供安全凭证输入框、Secret 管理或受保护的授权流程时，主动打开该入口，让用户直接填写 Key。不要读取、回显、复制到对话或代替用户记录 Key。
5. 用户完成安全填写后，继续保存连接、触发重载、检查工具列表并执行只读验证，不让用户自行判断是否安装成功。
6. 客户端无法由 Skill 调起配置时，先确认客户端名称和版本，再根据其实际界面给出手动步骤；不要臆造菜单、配置路径或传输类型。

自动安装只负责建立客户端连接，不能代替用户登录平台、选择站点、创建 Key 或确认权限。

客户端提供可安全完成上述操作的授权页面或用户接管步骤时，应主动打开对应页面并等待用户完成，不用文字教程替代可执行的安装动作。

## 自动化优先级

按以下顺序使用当前客户端提供的能力，选择能够实际执行的最高级别：

1. **MCP 连接管理接口**：直接检查、创建或更新连接，打开安全凭证输入，重载并验证。
2. **MCP 依赖安装界面**：调起 `ceying-geo` 安装项并预填传输方式，引导用户补充地址和 Key 后继续验证。
3. **受控配置编辑能力**：读取实际配置结构后进行结构化修改；修改前保留原配置，不用字符串拼接破坏其他服务配置。
4. **纯手动客户端**：提供与已确认客户端名称和版本对应的界面步骤，并在用户完成后继续工具发现验证。

不得因为手动说明更容易而跳过客户端已经提供的自动安装能力。不得修改未知格式的配置文件，也不得在没有安全凭证能力时把 Key 写入普通文本文件。

## 获取服务地址与 MCP Key

引导用户完成以下操作：

1. 登录策影GEO平台并切换到需要操作的站点。
2. 进入“账号与权益 > MCP Server”。
3. 复制页面展示的当前站点 MCP Server 公网地址。生产环境必须使用有效 HTTPS 地址。
4. 创建新的 MCP Key，填写可识别的用途名称和适当的有效期。
5. 根据当前目标选择最小业务权限。不要为了减少配置步骤默认授予全部 Scope。
6. 创建后立即将只显示一次的 Key 填入客户端安全凭证区域；不要粘贴到聊天消息、Skill 文件、URL、代码仓库或日志。

Key 由策影GEO平台生成。没有平台账号、可用站点或创建 Key 的套餐权限时，停止配置并明确指出缺少的前置条件。

## 客户端连接参数

客户端配置必须使用以下实际值：

- 连接名称：`ceying-geo`。
- 传输方式：优先使用平台页面提供的 Streamable HTTP 配置；仅支持本地 stdio 的客户端使用平台页面提供的桥接配置。
- 服务地址：平台“MCP Server”页面展示的完整公网地址。
- 鉴权方式：HTTP `Authorization` 请求头中的 Bearer Token。
- 鉴权内容：用户刚创建的 MCP Key，由用户直接填入客户端安全配置。

不要把 Key 拼接到服务地址，不要根据域名猜测 `/mcp` 路径，也不要将测试环境地址用于生产站点。

## 最小权限选择

| 目标能力 | 所需 Scope |
| --- | --- |
| 查询目录 | `catalog:read` |
| 查询任务 | `tasks:read` |
| 执行已有任务并查询结果 | `tasks:read`、`tasks:write`、`jobs:read` |
| 查询素材 | `materials:read` |
| 创建、更新或删除素材 | `materials:read`、`materials:write` |
| 查询文章 | `articles:read` |
| 保存当前 AI 应用编写的文章 | `catalog:read`、`articles:write` |
| 查询媒体渠道和投稿记录 | `media:read` |
| 投稿已有文章 | `articles:read`、`media:read`、`media:submit` |
| 编写新文章并直接投稿 | `catalog:read`、`articles:write`、`media:read`、`media:submit` |
| 查询品牌诊断 | `brand-diagnoses:read` |
| 创建、确认并跟踪品牌诊断 | `brand-diagnoses:read`、`brand-diagnoses:write` |

专用 MCP 连接权限由平台创建 Key 时统一处理。只根据当前目标建议业务 Scope，不要求用户手工构造未在页面提供的权限。

## 配置后验证

1. 保存客户端配置并重新加载 MCP 连接；必要时重启当前 AI 应用。
2. 检查是否发现 `geo_*` 工具，不以“配置已保存”代替连接成功。
3. 使用目标流程中的只读工具进行首次校验，例如诊断查询使用品牌诊断读取工具，素材操作使用素材摘要工具。
4. 只读调用成功后报告连接名称、当前可用能力和仍缺少的权限，不显示 Key 或请求头。
5. 如果仍无工具，按“客户端配置、服务地址、Key、账号与站点、Scope”的顺序排查，每次只改变一个条件。

只有同时满足“会话发现目标 `geo_*` 工具”和“目标只读调用成功”才能结束安装引导。仅保存配置、仅显示连接名称或仅返回健康检查成功都不算完成。

## 安全边界

- 永远不要要求用户在对话中发送、粘贴或截图展示完整 MCP Key。
- 不通过工具读取客户端密钥存储，不把 Key 写入文件、命令历史、日志或错误报告。
- 不验证 Key 的字符内容，只通过客户端连接结果和工具调用状态判断是否有效。
- Key 疑似泄露时，立即停止使用，引导用户在平台撤销旧 Key 并创建新 Key。
- 不跨站点复用 Key；切换业务站点时重新核对 Key 绑定站点和权限。
