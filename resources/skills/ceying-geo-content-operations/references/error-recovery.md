# 错误与恢复

## 通用处理

| 状态或错误 | 处理方式 |
| --- | --- |
| `401` | 停止调用，提示用户在客户端检查 Key 是否完整、过期或撤销；不要要求用户把 Key 发到对话中。 |
| `403` | 根据缺失工具说明应补充的 Scope；站点停用时提示恢复站点状态。 |
| `404` | 重新查询当前账号和站点内的资源，不猜测编号，也不尝试跨账号访问。 |
| `409` | 保持原幂等键和原请求内容，等待处理中操作完成；载荷不一致时不要复用该键。 |
| `422` | 按返回信息修正字段、处理素材引用或套餐额度，不重复提交原错误请求。 |
| `429` | 按服务端提示等待并降低调用频率，不并发重试。 |
| `502`、`504` | 将结果视为未知，先查询业务状态；确需重放时使用原参数和原幂等键。 |

## 幂等记录

在当前会话中为每个写操作保留以下信息，直到取得明确结果：

- 操作类型。
- 目标资源编号。
- 完整业务参数摘要。
- `idempotency_key`。
- 已返回的文章、执行记录、投稿订单或诊断任务编号。

不得把同一个幂等键用于参数不同的操作。用户修改正文、渠道、问题、素材内容或删除范围后，视为新操作并生成新的幂等键。

## 投稿部分成功

1. 保存成功订单和失败渠道的独立结果。
2. 查询成功订单，避免因响应不完整误判失败。
3. 只对确认失败且尚未接单的渠道创建新操作。
4. 新的失败渠道集合使用新幂等键；该集合的网络重试继续复用新键。

## 缺少工具与权限

| 能力 | 所需 Scope |
| --- | --- |
| 查询目录 | `catalog:read` |
| 查询或执行任务 | `tasks:read`、`tasks:write`、`jobs:read` |
| 查询或管理素材 | `materials:read`、`materials:write` |
| 查询或保存文章 | `articles:read`、`articles:write` |
| 查询渠道与投稿 | `media:read`、`media:submit` |
| 查询或执行品牌诊断 | `brand-diagnoses:read`、`brand-diagnoses:write` |

只建议当前目标真正需要的权限，不要求用户无条件授予全部 Scope。
