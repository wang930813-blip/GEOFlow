# GEO 内容生成、站内发布与媒体投稿

## 直达触发

| 用户表达 | 直接动作 | 工具 |
| --- | --- | --- |
| 写一篇文章、生成一篇文章并保存 | 编写并保存文章 | `geo_get_catalog` -> `geo_create_article` |
| 把这篇文章发到站点、发布到官网 | 发布已有文章到站点 | `geo_get_article` -> `geo_publish_article_to_site` |
| 写完后直接发到站点 | 编写、保存并站内发布 | `geo_get_catalog` -> `geo_create_article` -> `geo_publish_article_to_site` |
| 把已有文章投稿到媒体 | 投稿已有文章 | `geo_get_article` -> `geo_list_media_channels` -> `geo_get_media_channel` -> `geo_submit_article_to_media` |
| 写完直接投媒体 | 编写、保存并投稿 | `geo_get_catalog` -> `geo_list_media_channels` -> `geo_publish_article_to_media` |
| 查媒体渠道、查价格 | 查询渠道 | `geo_list_media_channels` 或 `geo_get_media_channel` |
| 查投稿进度、查投稿结果 | 查询投稿状态 | `geo_list_media_submissions` 或 `geo_get_media_submission` |

命中以上动作时，不先输出完整推广方案。只补齐阻塞执行的信息。

## 选择执行方式

- 用户要求由当前 AI 应用编写文章时使用本工作流，不调用 `geo_run_task`。
- 用户指定 ceying-geo 中已有文章发布到站点时，先用 `geo_get_article` 核对；只要文章未被人工拒绝，即可在用户确认后调用 `geo_publish_article_to_site` 自动通过并发布。
- 用户指定 ceying-geo 中已有文章投稿到媒体时，先用 `geo_get_article` 核对，再调用 `geo_submit_article_to_media`。
- 用户明确要求执行平台已有任务时，转到 `task-execution.md`。

当前 AI 应用直接编写并保存文章不会扣减 ceying-geo 的文章生成额度；站内发布不扣媒体投稿费用；媒体投稿仍按渠道实时售价结算。执行已有任务按任务成功生成结果消耗文章生成额度。

## GEO 内容要求

文章必须服务于明确的品牌认知、客户问题或 AI 答案占位目标，不生成只有宣传口号的通用软文。

按任务需要组织以下内容：

- 实体定义：品牌或产品是谁、属于什么品类。
- 业务关系：解决什么问题、为谁服务、适用于什么场景。
- 能力机制：如何提供价值，边界是什么。
- 可信证据：案例、数据、资质或第三方来源。
- 比较信息：可验证的选择标准、适用与不适用条件。
- FAQ：使用目标客户会实际提出的问题，不重复正文标题。

所有品牌事实、数据、客户名称、资质和绝对化主张必须来自用户确认或可验证素材。没有证据时删除相关表述或标记待确认，不自行写入“中国领先”“第一”“唯一”等结论。

## 编写并保存新文章

1. 收集文章目标、目标问题、受众、核心观点、品牌词、事实依据、长度、语气、必须包含或禁止出现的内容、发布时间要求。只追问阻塞执行的信息。
2. 调用 `geo_get_catalog` 获取有效作者和分类，不使用历史会话编号代替当前结果。
3. 需要参考素材时，调用 `geo_get_material_summary`、`geo_list_materials`、`geo_get_material` 和 `geo_list_material_items`，只读取与目标有关的数据。
4. 完成标题、正文、摘要、关键词和 SEO 描述，检查实体信息一致性和证据来源。分类与作者编号必须来自本次目录查询。
5. 调用 `geo_create_article` 保存文章，并记录文章编号和幂等键。
6. MCP 上传的新建文章默认已通过审核但不公开发布，不得把保存成功说成已公开发布。

## 发布文章到站点

1. 使用 `geo_list_articles` 或用户给出的文章编号定位文章。
2. 调用 `geo_get_article` 展示标题、状态、审核状态、分类和作者，防止发布错误文章。
3. 只要 `review_status` 不是 `rejected`，即可在用户确认后调用 `geo_publish_article_to_site`。
4. MCP 站内发布会自动写入 `auto_approved` 并公开发布，不需要人工审核，不调用审核接口。
5. 如果文章已被人工拒绝，停止发布并说明需要先修正文章内容；不要覆盖拒绝状态。
6. 发布成功后返回文章编号、`status`、`review_status`、`published_at`、`slug` 和可访问站点路径信息。

## 投稿已有文章

1. 使用 `geo_list_articles` 或用户给出的文章编号定位文章。
2. 调用 `geo_get_article` 展示标题和关键信息，防止投错文章。
3. 检查文章是否符合当前品牌目标、事实依据和渠道要求；不擅自改写平台已有文章。
4. 调用 `geo_list_media_channels` 查询候选渠道。结果不唯一时列出候选，让用户选择明确的媒体资源编号。
5. 对最终渠道调用 `geo_get_media_channel`，核对可用状态、当前售价、媒体类型和限制。
6. 未获得一次性自动授权时，展示文章标题、渠道编号、渠道名称、单价和预计总价，等待确认。
7. 调用 `geo_submit_article_to_media`，保存稳定幂等键和订单编号。
8. 调用 `geo_get_media_submission` 分渠道查询，直到每个订单得到明确状态。

## 编写并直接投稿

1. 先按“编写并保存新文章”准备文章内容、作者和分类。
2. 查询并确认媒体渠道及实时价格。
3. 未获得一次性自动授权时，展示文章预览、渠道编号、渠道名称、单价和预计总价，等待确认。
4. 调用 `geo_publish_article_to_media`。单次最多提交二十个媒体资源编号，并为本次操作生成和保留稳定的 `idempotency_key`。
5. 保存文章编号与各投稿订单编号，调用 `geo_get_media_submission` 跟踪每个订单直到明确终态。

## 查询投稿结果

1. 用户给出投稿订单编号时，直接调用 `geo_get_media_submission`。
2. 用户只给出文章、渠道或时间范围时，调用 `geo_list_media_submissions` 筛选。
3. 查询结果只按平台返回说明：待安排、发布中、已发布、退稿、失败、发布链接和失败原因。
4. 查询动作不得触发新的投稿。

## 一次性自动授权

只有以下条件同时满足时才直接执行外部媒体投稿：

- 用户明确表示最终文章无需再次审稿，可以生成后直接投稿。
- 用户明确指定渠道，或查询结果能够唯一匹配目标渠道。
- 用户明确给出最高总金额。
- 当前实时总价不超过最高总金额。
- 作者、分类、文章正文和渠道状态均有效。

任何条件不满足都停止在预览阶段，不自行放宽预算或替换渠道。

站内发布的一次性授权可用于未被拒绝的文章。文章处于 `pending` 时，`geo_publish_article_to_site` 会自动通过并发布；文章处于 `rejected` 或其他明确不可发布状态时，必须停止并提示先修正内容。

## 部分失败

- 查询所有成功返回的投稿订单，确认已接单渠道。
- 不重放包含成功渠道的原始多渠道请求。
- 将失败渠道组成新的投稿操作并使用新幂等键；同一新操作网络重试继续使用该键。
- 失败退款、最终费用和状态只按 MCP 返回结果说明，不自行推算退款金额。
