# 潜客挖掘与客户开发

## 使用边界

本流程只在用户明确要求执行线索采集、评论采集、企业搜索、联系方式查询、客户开发或客户触达时使用。用户只是泛化表达“找客户”“怎么获客”“怎么推广带来客户”时，先读取 [customer-acquisition-growth.md](customer-acquisition-growth.md) 输出完整获客推广曝光方案，不直接进入本流程。

潜客挖掘 MCP 是独立于 ceying-geo 的本地 MCP 服务。它的连接是否成功，以当前会话实际发现 `qw_mcp_list` 和 `qw_mcp_get` 为准；具体业务工具必须通过 `qw_mcp_list` 发现，再通过 `qw_mcp_get` 获取参数 schema。

## 连接预检

1. 检查当前会话是否发现 `qw_mcp_list` 和 `qw_mcp_get`。
2. 未发现时，暂停潜客挖掘、企业搜索和客户触达执行，不继续询问关键词或任务参数。
3. 立即检查客户端是否支持 MCP 连接管理或依赖安装；支持时主动创建或修复连接。
4. 推荐连接名称使用 `qian-ke-wa-jue` 或“潜客挖掘”。判断连接成功只看工具发现结果，不依赖连接名称。
5. 服务地址使用本地潜客挖掘 MCP 暴露的 `http://localhost:8000/mcp`，除非用户或工具返回了当前环境的其他真实地址。
6. 该本地 MCP 依赖“AI获客工具”桌面端已打开并登录。未登录或服务不可用时，引导用户先启动桌面端并确认本地 MCP 服务运行。
7. 不为潜客挖掘 MCP 臆造 Key、账号、远程域名或权限字段；只有客户端或该 MCP 明确要求时才引导用户配置对应凭证。
8. 连接后调用 `qw_mcp_list`，再对目标工具调用 `qw_mcp_get`。只有目标工具 schema 可用时才进入参数确认。

## 任务路由

| 用户目标 | 优先工具匹配 |
| --- | --- |
| 抖音获客、评论采集、按作品或内容关键词找潜客 | 在 `qw_mcp_list` 返回结果中匹配描述包含采集、获客、评论、任务状态或结果查询的工具 |
| 已有获客任务后要开发客户、回复评论或触达客户 | 在 `qw_mcp_list` 返回结果中匹配描述包含开发、触达、回复、私信、任务状态或结果查询的工具 |
| 搜索某企业、按行业或地区找公司 | 优先使用 `search_company_info` |
| 获取企业电话、邮箱、微信等联系方式 | 先取得企业搜索结果中的 `id`，再使用 `get_company_contact_list` |
| 品牌推广与获客联动 | 先读取获客推广曝光整体方案和对应 GEO 参考文件，再按本文件执行潜客任务 |

## 挖掘客户

1. 调用 `qw_mcp_list` 获取可用工具和描述，根据用户目标匹配最合适的获客工具。
2. 调用 `qw_mcp_get` 获取该工具的完整参数 schema，以 `required`、参数类型和字段说明作为唯一传参依据。
3. 如果必填参数包含作品关键词、视频关键词、评论关键词或内容关键词，检查用户是否已提供。
4. 用户未提供关键词时，先询问行业和目标客户；根据行业生成三到五个作品关键词和三到五个内容关键词供用户选择。
5. 客户端提供表单或用户确认工具时，优先使用该能力让用户单选作品关键词、多选内容关键词；否则在对话中一次性列出选项并等待确认。
6. 对 schema 中所有必填参数逐项确认；可选参数先询问用户是否需要更多筛选条件，用户确认后再列出。
7. 数组、日期范围、城市列表等字段严格按 schema 要求传值。
8. 调用目标工具启动任务。获客任务为异步执行，调用后立即返回任务编号，不等待完整结果。
9. 如工具提供状态查询和结果查询，保存任务编号并轮询状态；最多轮询六次，每次间隔约十秒，避免无限等待。
10. 状态仍在执行中时，同时查询当前已挖掘数据并汇报进度；状态完成后查询完整结果。

## 开发客户

1. 确认会话内最近一次获客任务编号；没有可用编号时，让用户提供任务编号。
2. 调用 `qw_mcp_list` 匹配客户开发、触达、回复评论、私信或任务状态相关工具。
3. 调用 `qw_mcp_get` 获取目标工具 schema。
4. 根据 schema 让用户选择触达方式；如果触达方式包含回复评论，确认是否由当前 AI 应用生成回复内容。
5. 如果需要回复内容列表、私信内容列表或评论内容列表，先调用文案库内容列表相关工具获取可选项，再让用户选择。三个内容列表每次独立选择，不复用上一轮选择。
6. 调用目标工具启动触达任务。触达任务为异步执行，调用后立即返回触达任务编号。
7. 如工具提供触达任务状态查询，最多轮询六次；当完成数、失败数、跳过数等状态数量之和等于子任务总数时，汇总执行状态。

## 企业获客

1. 根据用户意图选择 `search_field`：
   - `companyName`：按企业名称或公司名称搜索。
   - `manageScope`：按经营范围或行业关键词搜索。
   - `businessLocation`：按企业所在地、城市或地区搜索。
2. 用户只说“找某类公司”但搜索字段不明确时，先追问是按公司名称、经营范围还是地区搜索。
3. 用户表达模糊时，将自然语言整理为可搜索词，并说明采用的搜索字段。
4. 调用 `search_company_info` 执行搜索，默认查询第一页。
5. 如果返回还有下一页，先展示当前结果；用户要求继续查看更多时再翻页。
6. 如果用户只需要企业列表，直接整理结果；如果用户需要电话、邮箱、微信等联系方式，先让用户从企业列表中选定目标企业 `id`。
7. 使用 `get_company_contact_list` 查询联系方式。该工具需要企业搜索结果中的 `id`，不是企业名称。
8. 搜索结果为空时，优先尝试切换搜索字段、缩小地区或调整经营范围关键词，不重复提交同一无效查询。

## GEO 与潜客联动

1. 先用品牌、产品、行业和目标客户判断联动价值；不确定时问用户本次更重视品牌认知还是线索数量。
2. 需要内容背书时，先走 ceying-geo 的品牌诊断、定位、素材、文章或媒体发布流程。
3. 需要线索转化时，将 GEO 输出的目标客户、行业词、场景词和内容主题转成潜客挖掘关键词。
4. 获得线索后，用 GEO 内容资产生成触达话术，保持品牌事实、产品描述和案例证据一致。
5. 触达前必须让用户确认触达方式、内容范围、数量和合规边界。
6. 结果复盘时分开报告品牌侧指标和获客侧指标，不把曝光、线索和成交混为同一结果。

## 结果呈现

企业列表优先展示企业名称、所在地、经营状态、统一社会信用代码、注册日期、法人、注册资本和企业 ID。

企业联系方式按手机、固话、邮箱、微信和其他类型分组，展示联系方式类型、联系人、号码或账号、来源。

评论线索和获客结果按任务编号、使用关键词、客户总数、线索来源、用户昵称或企业名称、匹配原因、可执行下一步整理。涉及个人信息时只展示工具返回且用户有权处理的必要字段。

触达任务结果按触达任务编号、触达方式、子任务总数、成功数、失败数、跳过数和失败原因汇总。

## 错误处理

| 状态 | 处理方式 |
| --- | --- |
| 未发现 `qw_mcp_list` 或 `qw_mcp_get` | 进入连接预检，不继续潜客执行 |
| 桌面端未打开或未登录 | 引导用户打开并登录“AI获客工具”桌面端后重试 |
| 参数类型错误 | 重新读取 `qw_mcp_get` schema，按字段类型修正后重试 |
| 任务长时间执行中 | 汇报当前已获取数量，建议检查桌面端和网络状态 |
| 企业联系方式为空 | 返回企业列表和空结果，不编造电话、邮箱或联系人 |
| 触达失败或部分失败 | 按子任务状态分别报告，不自动重试可能造成重复触达的操作 |
