# 账号体系

## 目的

使用宿主应用自己的账号体系作为唯一可信来源。三方平台提供 API Key、授权会话、账号列表、发布流程和发布记录，但它不知道你应用里的哪个账号属于哪个用户，除非宿主应用自己保存这层映射关系。

## 推荐数据模型

在宿主应用中保存等价记录即可，名称可以不同。

### 用户或租户

保存拥有发布权限的应用内身份：

- `id`
- `name`
- 可选租户/组织字段
- 状态

### API Key 配置

可以使用一个共享三方平台 API Key，也可以每个租户一个 Key。对大多数 SaaS 系统来说，一个共享 Key 可以接受，但前提是应用必须保存严格的“用户到平台账号”绑定关系。

建议保存：

- Key 所属方/作用域
- 加密后的 API Key，或密钥存储引用
- 启用状态
- 内部默认 Base URL：`https://aitoearn.cn`
- 对用户说明时不要暴露服务商名称；普通说明使用“三方平台接口地址”，只有生成可直接执行的请求命令时才写真实 Base URL。

### 账号分组

共享 API Key 下必须给每个宿主应用用户/租户建立独立账号分组。分组是区分“哪个外部账号属于哪个应用用户”的第一层边界。

建议保存：

- 用户/租户 ID
- 三方平台分组 ID：`groupId`
- 随机分组名称
- 是否默认分组
- 创建时间、最后同步时间
- 原始响应

本地没有当前用户/租户的分组记录时，静默创建分组：

```text
POST /api/v2/channels/account-groups
请求体: { "name": "<随机分组名称>" }
```

随机分组名称用于机器识别即可，不要暴露用户手机号、昵称、公司名等隐私信息。推荐格式：

```text
gpf-<8位随机小写字母数字>-<时间戳>
```

创建成功后保存响应中的 `data.id` 作为当前用户/租户的 `groupId`。如果创建失败，停止授权/发布流程并返回结构化错误。

### 授权会话

保存每一次授权尝试：

- 用户/租户 ID
- 平台：`douyin` 或 `KWAT`
- 当前用户/租户的三方平台 `groupId`
- 三方平台 session id
- 授权 URL 或二维码 data URL
- 状态：pending、authorized、failed、expired
- 过期时间
- 使用共享 API Key 时，授权前已知的三方平台 accountId 列表
- 授权成功后确认的平台账号 ID
- 原始响应，便于诊断

### 平台账号绑定

只保存已经安全映射到用户/租户的平台账号：

- 用户/租户 ID
- 三方平台 `groupId`
- 平台
- 三方平台 accountId
- 展示名称/昵称
- 头像，如有
- 授权状态：authorized、unavailable、unbound
- 绑定时间和最后同步时间
- 原始账号数据

除非产品明确支持多个用户共享同一个第三方账号，否则应增加唯一约束，避免同一个第三方账号被误绑定到多个用户：

```text
unique(platform, provider_account_id)
```

如果产品支持共享账号，也应通过管理员显式共享，不要通过同步自动共享。

### 发布记录

保存每一次发布请求和每个平台发布项：

- 用户/租户 ID
- 内容类型：video
- 标题、描述、媒体 URL、封面 URL
- 目标平台和账号 ID
- 外部 flow id
- 各平台 task 或 record id
- 状态
- 必要的确认链接
- 发布成功后的作品链接
- 错误信息、code、requestId、原始响应

## 共享 API Key 下的安全授权流程

当一个三方平台 API Key 服务多个应用用户时：

1. 先读取宿主应用本地分组记录；没有当前用户/租户分组时，静默创建账号分组并保存 `groupId`。
2. 开始授权前，只获取当前 `groupId` 下目标平台已有的三方平台 accountId，并保存到授权会话。如果账号列表接口不能按 `groupId` 查询，也必须按返回数据中的 `groupId` 在本地过滤。
3. 发起平台授权时必须带当前分组：`GET /api/v2/channels/accounts/auth/{platform}?groupId=<当前用户分组ID>`，同时保存 `sessionId` 和授权 URL/二维码。
4. 授权成功后，再次获取当前 `groupId` 下目标平台账号列表。
5. 如果授权状态接口返回 accountId，优先使用该值，但仍要确认该账号属于当前 `groupId`。
6. 否则用授权后的当前分组账号列表减去授权前当前分组账号列表，识别新账号。
7. 只把唯一且可安全识别、并且 `groupId` 匹配当前用户/租户分组的账号绑定到当前用户/租户。
8. 如果候选账号为 0 个或多个，停止并要求管理员确认。
9. 如果候选账号已经绑定到其他用户/租户，停止并提示重复绑定冲突。

不要只根据昵称、头像、最新更新时间或平台来绑定账号。不要读取或绑定默认分组账号，除非管理员显式把该账号迁移或共享给当前用户。

## 手动同步规则

普通用户触发同步时，只刷新已经绑定到该用户/租户、且 `groupId` 匹配当前用户/租户分组的账号状态。不要从三方平台全局账号列表、默认分组或其他用户分组导入未知账号。

管理员工具可以查看全局账号池用于排查问题，但把全局账号绑定到用户必须是显式操作。
