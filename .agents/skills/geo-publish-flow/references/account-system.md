# 账号体系

## 目的

使用宿主应用自己的账号体系作为唯一可信来源。三方平台提供 API Key、授权会话、账号列表、发布流程和发布记录，但它不知道你应用里的哪个账号属于哪个用户，除非宿主应用自己保存这层映射关系。

## 推荐数据模型

在宿主应用中保存等价记录即可，名称可以不同。

### 用户或租户

保存拥有发布权限的应用内身份：

- `id`
- `name`
- 可选租户/组织字段
- 状态

### API Key 配置

可以使用一个共享三方平台 API Key，也可以每个租户一个 Key。对大多数 SaaS 系统来说，一个共享 Key 可以接受，但前提是应用必须保存严格的“用户到平台账号”绑定关系。

建议保存：

- Key 所属方/作用域
- 加密后的 API Key，或密钥存储引用
- 启用状态
- Base URL，国内站通常为 `https://aitoearn.cn`

### 授权会话

保存每一次授权尝试：

- 用户/租户 ID
- 平台：`douyin` 或 `KWAT`
- 三方平台 session id
- 授权 URL 或二维码 data URL
- 状态：pending、authorized、failed、expired
- 过期时间
- 使用共享 API Key 时，授权前已知的三方平台 accountId 列表
- 授权成功后确认的平台账号 ID
- 原始响应，便于诊断

### 平台账号绑定

只保存已经安全映射到用户/租户的平台账号：

- 用户/租户 ID
- 平台
- 三方平台 accountId
- 展示名称/昵称
- 头像，如有
- 授权状态：authorized、unavailable、unbound
- 绑定时间和最后同步时间
- 原始账号数据

除非产品明确支持多个用户共享同一个第三方账号，否则应增加唯一约束，避免同一个第三方账号被误绑定到多个用户：

```text
unique(platform, provider_account_id)
```

如果产品支持共享账号，也应通过管理员显式共享，不要通过同步自动共享。

### 发布记录

保存每一次发布请求和每个平台发布项：

- 用户/租户 ID
- 内容类型：video
- 标题、描述、媒体 URL、封面 URL
- 目标平台和账号 ID
- 外部 flow id
- 各平台 task 或 record id
- 状态
- 必要的确认链接
- 发布成功后的作品链接
- 错误信息、code、requestId、原始响应

## 共享 API Key 下的安全授权流程

当一个三方平台 API Key 服务多个应用用户时：

1. 开始授权前，获取目标平台当前已有的三方平台 accountId，并保存到授权会话。
2. 发起平台授权，保存 `sessionId` 和授权 URL/二维码。
3. 授权成功后，再次获取目标平台账号列表。
4. 如果授权状态接口返回 accountId，优先使用该值。
5. 否则用授权后的账号列表减去授权前账号列表，识别新账号。
6. 只把唯一且可安全识别的账号绑定到当前用户/租户。
7. 如果候选账号为 0 个或多个，停止并要求管理员确认。
8. 如果候选账号已经绑定到其他用户/租户，停止并提示重复绑定冲突。

不要只根据昵称、头像、最新更新时间或平台来绑定账号。

## 手动同步规则

普通用户触发同步时，只刷新已经绑定到该用户/租户的账号状态。不要从三方平台全局账号列表导入未知账号。

管理员工具可以查看全局账号池用于排查问题，但把全局账号绑定到用户必须是显式操作。
