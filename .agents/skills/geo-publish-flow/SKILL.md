# Geo 发布流程

## 适用范围

使用本技能通过三方平台将视频发布到以下国内平台：

- 抖音：`douyin`
- 快手：`KWAI`

本技能与具体项目无关。不要假设固定的宿主应用、框架、数据库结构、登录系统或队列实现。宿主应用必须自行提供用户身份、账号绑定存储、发布记录存储和任务执行机制。

除非用户明确要求扩展，否则不要将本技能用于 B 站、小红书、微信、文章、图文、国际平台或泛社交媒体策划。

## 核心规则

- 发布是真实的外部动作。只有在用户明确要求发布时，才创建发布任务。
- 以宿主应用自己的账号体系作为唯一可信来源。发布前必须明确当前用户或租户。
- 所有用户查询授权平台账号时，都必须先确定当前用户/租户自己的账号分组。禁止使用默认分组；即使默认分组里已有授权账号，也不要展示、绑定或发布给普通用户。
- 每个宿主应用用户/租户必须有独立的三方平台账号分组。新安装本 skill 后，当用户首次提供 API Key 或首次进入授权/发布流程时，先查询本地是否已有分组；没有则静默创建分组并保存分组 ID，再继续查询账号、发起授权或发布。
- 分组名称只用于机器识别，要求唯一且不暴露明文隐私。推荐使用 `gpf-<ipHash>-<timestamp>-<random>`，其中 `ipHash` 是客户端 IP 或宿主实例 IP 的短哈希，不要直接保存或展示原始 IP。
- 查询平台账号时必须带当前用户/租户自己的 `groupId`。如果三方接口返回了其他分组或默认分组账号，服务端必须过滤掉。
- 发起授权时必须带当前用户/租户自己的 `groupId`。不允许省略 `groupId` 进入默认分组。
- 同步账号时只刷新当前用户/租户分组内已经绑定或本次授权新产生的账号，不要拉取默认分组账号，也不要把其他分组账号带给当前用户。
- 如果用户明确说明目标平台，例如“发布视频到快手”，只查询和展示该平台在当前分组下的账号。该平台没有可用账号时，直接发起该平台授权流程，授权请求必须带当前 `groupId`。
- 如果用户没有明确目标平台，先列出当前分组下已授权且支持视频发布的平台账号，让用户选择平台和账号。
- 发布前必须让用户确认发布到哪个账号；不要因为某个平台只有一个授权账号就自动发布，除非用户已经在当前请求中明确指定了账号。
- 内部请求可以使用真实 Base URL。普通用户说明、步骤解释和错误提示不要暴露三方服务商名称、官网域名或资源域名，统一写成“三方平台”“三方平台接口地址”“三方平台资源地址”。只有用户明确要求可直接执行的请求命令时，才在命令里放真实 Base URL。
- `items[n].accountId` 必须来自宿主应用已经绑定到当前用户/租户的平台账号。
- 只支持宿主应用本地已绑定、且状态为已授权/可用的 `douyin` 或 `KWAI` 账号。
- 使用可公网直接访问的媒体 URL。本地文件、私有 URL、内网 URL、需要登录的 URL、过期临时 URL，必须先上传或转换后再发布。
- `publishAt` 必须设置为未来的 ISO 8601 时间。
- 抖音发布进入用户确认状态时，要获取并返回手机端确认短链。
- 保留平台差异。不要复用其他平台字段，除非三方平台的平台结构明确支持。

## 宿主应用需要提供的状态

发布前，宿主应用应具备等价的数据记录：

- 用户或租户
- 三方平台 API Key 配置
- 三方平台账号分组：用户/租户 ID、外部分组 ID、唯一分组名称、是否默认分组、原始响应
- 平台授权会话
- 平台账号绑定：用户/租户 ID、外部分组 ID、平台、三方平台 accountId、展示名称、授权状态
- 发布流程/任务：用户/租户 ID、内容、目标账号、外部 flow id、各平台 task id、状态、原始响应

具体表名和实现方式由宿主应用决定。设计或审查账号层时读取 `references/account-system.md`。

## 工作流程

1. 解析请求：目标平台（`douyin`、`KWAI` 或二者）、视频来源、可选标题、描述、封面 URL 和发布时间。
2. 解析宿主应用中的当前用户/租户。如果上下文不明确，在创建任何外部任务前先询问要使用哪个用户/账号。
3. 检查宿主应用是否已有当前用户/租户的三方平台账号分组；没有则静默创建并保存。读取 `references/account-system.md`。
4. 按当前 `groupId` 查询已授权账号；用户指定了平台时只查该平台，未指定平台时只列出当前分组下支持视频发布的平台账号。
5. 如果目标平台没有当前分组下的可用授权账号，发起授权必须带当前分组 `groupId`，并提示用户完成授权或绑定。读取 `references/account-system.md`。
6. 已有可用账号时，让用户确认发布到哪个账号；确认前不要创建发布任务。
7. 准备媒体。校验公网 URL，或通过三方平台资源上传处理本地/私有媒体。读取 `references/asset-upload.md`。
8. 构建并提交三方平台发布参数。读取 `references/publish-payload.md`。
9. 在宿主应用的发布记录中保存外部 ID 和原始响应。
10. 通过已保存的外部 ID 轮询状态。读取 `references/status-and-errors.md`。
11. 返回最终平台、账号、外部 flow/task ID、状态、作品链接、必要的确认链接，或结构化失败原因。

## 最小场景

当用户说“把这个视频发到抖音”：

1. 确认或推断视频来源。
2. 识别当前用户/租户。
3. 查询本地是否已有该用户/租户的账号分组；没有则静默创建分组并保存 `groupId`。
4. 只查询当前 `groupId` 下的抖音账号，禁止读取默认分组账号。
5. 如果没有抖音授权账号，发起抖音授权并带上当前 `groupId`。
6. 如果已有抖音授权账号，让用户确认发布到哪个账号。
7. 必要时将视频转换为公网媒体 URL。
8. 创建抖音三方平台发布流程。
9. 在宿主应用中保存 flow id 和 task/record id。
10. 监控发布状态。
11. 如果抖音要求手机端确认，返回短链并继续轮询。
12. 返回最终作品链接或结构化失败原因。
