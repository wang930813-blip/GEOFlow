# 品牌诊断回答快照设计

## 目标

为每条品牌诊断“问题 x 模型回答”提供无需登录的系统快照链接，并允许超级管理员为回答补充官方平台对话链接。

## 数据设计

在 `brand_diagnosis_results` 增加：

- `snapshot_token`：48 位随机公开令牌，唯一索引；历史结果在迁移中补齐，新结果由模型事件自动生成。
- `snapshot_payload`：冻结品牌、问题、模型回答、平台、诊断时间和有效引用来源；有回答的历史结果在迁移中补齐，新结果在模型处理成功后立即保存。失败且没有回答的结果不生成空快照。
- `official_share_url`：可选官方对话链接。
- `official_share_updated_by`、`official_share_updated_at`：记录最后维护人和时间。

公开链接只使用随机令牌，不暴露连续结果 ID。公开页面只读取冻结的 `snapshot_payload`，后续重跑、修改问题或替换引用来源不会改变已经生成的快照。官方链接不属于冻结内容，可由超管后续维护。

## 页面与权限

- 公开快照：`/brand-diagnosis/snapshot/{token}`，无需登录，设置 `noindex`，展示平台、问题、回答、来源和诊断时间。
- 诊断列表与报告：所有有权查看该诊断的后台角色都能打开系统快照；官方链接存在时也可查看。
- 官方链接管理：独立后台页面，一次展示整次诊断的全部回答并一次保存所有链接。
- 只有 `super_admin`/`superadmin` 可以打开和提交官方链接管理页；普通用户、直营账号和代理账号均返回 403。

## 校验与安全

- 引用来源只展示有效的 `http`/`https` URL。
- 官方链接仅接受 `http`/`https` URL，必须匹配对应模型的官方域名，空值表示清除。
- 提交的结果 ID 必须全部属于当前诊断记录，禁止跨记录更新。
- 批量提交只更新发生变化的链接，不覆盖未变化记录的维护人和维护时间。
- 外链统一新窗口打开并添加 `noopener noreferrer`。
- 不在公开快照中输出后台账号、站点归属、原始 API 响应或模型密钥信息。

## 批量方式

管理页按问题顺序展示所有平台回答，每条一个 URL 输入框；一个表单一次提交并保存全部结果。每次诊断通常最多 20 条回答，因此不引入额外导入格式，避免问题和链接错位。

## 测试

- 新旧诊断结果均有唯一快照令牌，成功回答生成冻结载荷，失败结果不展示空快照入口。
- 正确令牌无需登录可访问，错误令牌返回友好 404。
- 快照展示回答和有效引用，不泄露原始响应。
- 快照内容在首次生成后保持不变，并且登录其他站点账号时仍可按公开令牌查看完整内容。
- 超管可以一次新增、修改、清除多条官方链接。
- 危险引用协议、伪装域名和非对应平台官方域名会被拒绝。
- 非超管无法访问或提交管理接口。
- 诊断列表和报告正确展示快照及官方链接入口。
