# 子品牌网站独立部署资料清单

本文档用于单独部署一套子品牌网站前收集客户资料、确认三方账号与费用、梳理系统内需要替换或配置的品牌内容。实际密钥不要写入本文档正文，建议通过密码管理器、加密压缩包或受控运维通道交付。

## 1. 部署目标

子品牌独立部署通常包含：

- 一套独立域名访问的后台系统。
- 一个或多个前台内容站点。
- 独立数据库、Redis、队列、文件存储和运行容器。
- 独立品牌展示文案、Logo、站点 SEO 信息。
- 独立 AI 模型、媒体投稿平台、品牌诊断平台等三方接口配置。

如果只是同一套平台中新增一个客户站点，则不需要独立服务器和独立 `.env.prod`；如果是白标/子品牌独立交付，建议按本文档准备完整资料。

## 2. 客户必须提供

| 分类 | 资料项 | 是否必须 | 用途 | 备注 |
| --- | --- | --- | --- | --- |
| 域名 | 后台访问域名 | 必须 | `APP_URL`、后台登录入口、API 回调 | 例如 `geo.xxx.com` |
| 域名 | 前台站点域名 | 必须 | 绑定 `sites.domain`，用户内容站访问 | 创建后系统内一般不建议修改 |
| 域名 | 是否使用二级随机站点域名 | 可选 | 注册用户自动生成前台域名 | 对应 `GEOFLOW_CUSTOMER_SITE_DOMAIN_BASE` |
| 域名 | DNS 管理权限 | 必须 | 解析 A/CNAME、SSL 证书签发 | 需确认客户自己解析还是我方代管 |
| 备案 | ICP 备案主体与备案号 | 国内部署建议必须 | 页脚、合规展示 | 如域名接入国内服务器/CDN，需提前确认 |
| 服务器 | 服务器公网 IP | 必须 | 部署 Docker、绑定域名 | 建议 2C4G 起步，视诊断/任务量提高 |
| 服务器 | SSH 登录方式 | 必须 | 发布、排障、备份 | 建议密钥登录，禁用弱密码 |
| 服务器 | 操作系统 | 必须 | Docker 环境安装 | 建议 Ubuntu 22.04/24.04 或等价 Linux |
| 服务器 | 服务器区域 | 必须 | 影响访问速度和三方接口连通 | 国内服务器注意备案；海外注意国内访问质量 |
| 品牌 | 子品牌名称 | 必须 | 后台标题、前台站点、版权文案 | 例如“某某 GEO 平台” |
| 品牌 | 公司/主体名称 | 必须 | 前台页脚、监测报告、关键词库品牌识别 | 后续报表会优先从关键词库公司品牌名称取值 |
| 品牌 | 品牌 Logo | 必须 | 前台站点 Logo、后台展示、报表 Logo | 建议提供 PNG/SVG，透明底，深浅色版本 |
| 品牌 | favicon | 建议 | 浏览器页签图标 | `.ico` 或 PNG |
| 品牌 | 监测中心报表 Logo | 建议 | 监测中心两类报表左上角 Logo | 可与站点 Logo 不同，只允许超管设置 |
| 品牌 | 品牌主色/辅色 | 建议 | 后续 UI 白标或物料统一 | 当前系统大部分样式可先不改，只做 Logo 和文案 |
| 品牌 | 品牌简介 | 必须 | 官网介绍、关键词库、品牌诊断默认信息 | 建议 200-500 字 |
| 品牌 | 核心业务/产品/服务 | 必须 | 文章生成、问题生成、监测报表品牌画像 | 建议列 5-10 条 |
| 品牌 | 目标客户/行业 | 建议 | 文章标题、问题变体、诊断问题生成 | 越具体，生成内容越稳定 |
| 品牌 | 联系方式 | 建议 | 前台页脚和联系区 | 电话、微信、邮箱、地址 |
| 品牌 | 收款/客服二维码 | 可选 | 前台联系模块 | 可配置多个二维码 |
| SEO | 首页标题、关键词、描述 | 必须 | 前台 `title/meta` | 对应站点设置 |
| SEO | 统计代码 | 可选 | 百度统计、CNZZ、GA 等 | 仅超管可配置更稳 |
| 内容 | 初始栏目分类 | 建议 | 前台导航、文章归类 | 没有则由我方按业务创建 |
| 内容 | 初始关键词库 | 建议 | 文章生成、AI 搜索检测、监测中心取值 | 至少准备品牌词、行业词、核心服务词 |
| 内容 | 初始知识库资料 | 建议 | RAG 写作、文章生成、品牌内容一致性 | 企业介绍、产品说明、案例、FAQ |
| 账号 | 首个超管账号信息 | 必须 | 初始化后台登录 | 手机号/邮箱/登录名/初始密码交付方式 |
| 账号 | 是否开放用户注册 | 必须确认 | 后台登录页是否显示注册入口 | 开启后需指定注册体验规格 |
| 套餐 | 注册体验规格 | 如开放注册则必须 | 新用户注册后自动开通免费规格 | 需确认额度、有效期、资源范围 |

## 3. 系统内品牌相关配置点

| 模块 | 配置内容 | 配置位置 | 说明 |
| --- | --- | --- | --- |
| 全局环境 | `APP_NAME`、`APP_URL`、`SITE_NAME`、`SITE_FULL_NAME`、`SITE_URL` | `.env.prod` | 控制系统基础名称和 URL |
| 后台入口 | `ADMIN_BASE_PATH` | `.env.prod` 或后台站点设置 | 例如 `/geo_admin`，上线后不要频繁修改 |
| 后台展示文案 | 快速开始标题、副标题、页脚品牌、版本、媒体平台展示名 | 超管后台「网站设置」中的后台展示设置弹窗 | 适合替换固定品牌字样 |
| 用户注册 | 注册开关、注册体验规格 | 超管后台「网站设置」中的注册设置弹窗 | 关闭则登录页不显示注册入口 |
| 前台站点 | 站点名称、副标题、描述、关键词、版权、Logo、favicon | 后台「网站设置」 | 用于官网/内容站展示 |
| 前台域名 | `sites.domain` | 超管站点管理 | 创建后不建议修改；代理不能修改站点 Logo |
| 监测报表 Logo | `monitoring_report_logo` | 超管站点管理 | 按站点配置，未配置时使用平台默认 Logo |
| 关键词库品牌 | 公司品牌名称、领域关键词、行业、品牌描述 | 后台「关键词库」 | 监测中心品牌名称、文章上下文、AI 搜索检测会使用 |
| 知识库 | 企业资料、产品资料、FAQ、案例 | 后台「知识库」 | 文章生成时会引用知识片段 |
| AI 模型 | Chat、Embedding、Image 模型 | 后台「AI 大模型」 | 用于文章生成、标题生成、关键词/问题变体、知识库向量化、图片生成 |
| 任务生成 | 默认模型、提示词、标题库、知识库、分类、作者 | 后台「任务管理」 | 子品牌上线前建议准备一套默认模板 |
| 媒体投稿 | 平台 API Key、媒体资源同步、销售价倍率、站点积分 | 后台「官媒/媒体投稿」相关页面 | 涉及三方成本和客户侧积分 |
| 品牌诊断 | 豆包、DeepSeek、千问、文心配置 | `.env.prod` | 当前品牌诊断四模型固定从配置读取 |
| 品牌诊断开放 API | API 开关、固定 API Key、归属超管 ID | `.env.prod` | 对外开放品牌诊断能力时启用 |
| 视频生成 | 视频接口地址和 API Key | `.env.prod` | 如子品牌需要视频生成能力则配置 |
| MCP/API | MCP 公网 URL、允许 Host、Token 权限 | `.env.prod` + 后台 API Token | 如要外部 Agent 调用才需要 |

## 4. 三方账号与费用清单

### 4.1 AI 大模型账号

| 用途 | 需要账号/Key | 是否必须 | 费用承担 | 备注 |
| --- | --- | --- | --- | --- |
| 文章生成、标题生成、关键词生成、问题变体 | OpenAI/DeepSeek/火山方舟/其它 OpenAI 兼容模型 API Key | 必须 | 客户或我方确认 | 后台 AI 大模型中配置 `api_url`、`api_key`、`model_id` |
| 知识库向量化 | Embedding 模型 API Key | 建议必须 | 客户或我方确认 | 知识库切片向量化使用；可用 OpenAI、智谱等兼容模型 |
| AI 图片生成 | 图片模型 API Key | 可选 | 客户或我方确认 | 任务需要自动配图时使用 |
| AI 搜索收录检测 | Chat 模型 API Key | 必须 | 客户或我方确认 | 当前检测平台扩展到 DeepSeek、豆包、千问、元宝、文心等展示，短期方案主要由配置的模型执行检测提示 |
| ChatGPT 官方能力 | OpenAI API Key | 视客户要求 | 客户或我方确认 | 如果明确要求使用 ChatGPT/OpenAI，则单独准备 |

### 4.2 品牌诊断四模型账号

| 平台 | 配置项 | 是否必须 | 备注 |
| --- | --- | --- | --- |
| 豆包/火山方舟 | `BRAND_DIAGNOSIS_DOUBAO_*` | 建议必须 | 品牌介绍联网检索、核心词提取、诊断回答都依赖 |
| DeepSeek | `BRAND_DIAGNOSIS_DEEPSEEK_*` | 建议 | 可复用豆包/火山方舟网关，也可单独配置 |
| 千问/阿里百炼 DashScope | `BRAND_DIAGNOSIS_QIANWEN_*` | 建议 | 需支持联网搜索返回来源的接口模式 |
| 文心/百度千帆 | `BRAND_DIAGNOSIS_WENXIN_*` | 建议 | 需开通对应模型和联网搜索能力 |
| 品牌诊断开放 API | `BRAND_DIAGNOSIS_OPEN_API_*` | 可选 | 对外开放接口时启用，API Key 固定一组即可 |

品牌诊断费用按模型调用次数、联网检索、Token 消耗计费。若客户要求四个平台都可用，需要客户提供四个平台可用余额或明确由我方统一承担。

### 4.3 官方媒体/媒体投稿平台账号

系统当前有两个媒体平台，后台展示名可以配置为“权威媒体”和“优质媒体”，但真实三方接口如下：

| 系统平台 ID | 当前展示名 | 实际客户端 | 三方平台 | 需要客户提供 | 费用说明 |
| --- | --- | --- | --- | --- | --- |
| 1 | 权威媒体 | `MediaDistributionClient` | 小青蛙/现有媒体开放平台 | API Base URL、API Key、账号余额 | 投稿按媒体资源成本价消耗 |
| 2 | 优质媒体 | `ChaoJiMeiJieClient` | 超级媒介 | 超级媒介 API Base URL、API Key、账号余额 | 投稿按超级媒介资源成本价消耗 |

媒体相关还需要确认：

- 是否允许客户投稿扣积分。
- 积分与人民币换算规则。
- 是否配置站点专属销售价或统一倍率。
- 是否同步网站媒体、自媒体、B2B 套餐资源。
- 投稿失败、取消、退款的费用归属规则。

## 5. 服务器与运维准备

| 项目 | 建议 |
| --- | --- |
| Docker | 安装 Docker Engine 与 Docker Compose |
| 端口 | 80、443 必须开放；内部端口如 18080、18081、18082 按部署方式决定是否暴露 |
| 数据库 | PostgreSQL + pgvector；生产环境需要持久化卷 |
| Redis | 用于队列、缓存、Session |
| 队列 | 文章生成、品牌诊断、媒体同步等依赖队列 worker |
| 备份 | 至少每日备份数据库和上传文件 |
| 日志 | 保留 Laravel 日志、Nginx 日志、Docker 容器日志 |
| 监控 | 建议监控 CPU、内存、磁盘、Redis、队列积压 |
| HTTPS | 必须配置 SSL 证书，尤其开放 MCP/API 时 |
| 安全 | 关闭 `APP_DEBUG`，设置强 `APP_KEY`、强后台密码、限制 SSH |

## 6. 上线前配置顺序

1. 准备服务器、Docker、域名解析和 SSL。
2. 填写 `.env.prod`：`APP_URL`、数据库、Redis、队列、后台路径、站点基础品牌名称。
3. 构建并启动生产容器，执行迁移和初始化超管。
4. 超管登录后配置后台展示文案、注册开关和体验规格。
5. 创建客户站点，绑定前台域名，设置监测中心报表 Logo。
6. 进入站点设置，配置前台站点名称、Logo、favicon、SEO、版权、联系方式。
7. 配置 AI 大模型：Chat、Embedding、Image。
8. 配置品牌诊断四模型 `.env.prod`，清理配置缓存并重启队列/容器。
9. 配置媒体平台账号 API Key，同步媒体资源，确认价格和积分。
10. 创建关键词库、知识库、分类、作者、提示词、标题库和默认任务。
11. 测试文章生成、定时发布、媒体投稿、品牌诊断、监测中心报表、分享链接。
12. 配置备份、日志巡检和异常告警。

## 9. 风险与确认项

- 三方 API Key 必须确认可用余额和模型权限，尤其是文心、千问的联网搜索能力。
- 国内域名接入国内服务器/CDN 前，备案状态会影响上线时间。
- 媒体投稿存在第三方审核、驳回、退款周期，不应承诺实时发布。
- 独立部署后，`APP_KEY` 不能丢失；丢失会影响已加密的 AI Key 和媒体 Key 解密。
- 前台域名创建后建议锁定，不要随意改；涉及已收录页面和分享链接。
- 客户若要求彻底白标 UI，除了本文档配置项，还需要单独评估后台固定文案、静态资源、主题样式和邮件模板。
